# Known issues and verification limits

- Prototype presentation uses static supplied FBX models with procedural attack/retreat/breakdown and construction feedback. No supplied animation clips, VFX/audio pack or dedicated child/robot/refinery asset was identified. Child is a smaller male-b model; security robot is a UFO/drone stand-in; refinery is a tower stand-in. All are explicit in the catalog and mapping. No asset downloads were performed.
- The UI is a self-contained IMGUI prototype with Input System board controls, rather than a production Canvas prefab hierarchy. Menu, help, settings and battle live in one dedicated scene rather than separate Bootstrap/MainMenu scenes. Safe area/ultrawide/mobile production polish has not been established; desktop landscape is the target.
- The image supplied later is a styling reference, not a pixel-perfect implementation or source of gameplay numbers.
- factory_plan.schema.json was missing from the supplied files. The schema was reconstructed from document 04; client and gateway have equivalent copies and strict parser/shape tests. The client implements this narrow contract, not an unrestricted JSON-schema engine.
- Live Ollama/model and hosted credentials were unavailable. No claim is made about model throughput, schema support on the user's eventual chosen model, provider permissions or live latency.
- Gateway is a minimal loopback Python service with a fixed OpenAI adapter and fake provider. HTTPS termination/deployment and session-token issuance are user configuration; no remote service was published. Its rate limit is per gateway process/shared session token; horizontal deployment requires shared rate/session storage.
- Gateway observation validation enforces default price/health/cap bounds. Update server validation alongside intentional authoring changes to those defaults; local and scripted modes consume authoring-derived legal options directly.
- Physics is not authoritative. No navigation, multiplayer, shop/progression, RAG, embedded model, refunds, repairs or village base were added.
- Fixed ticks and stable ordering are verified on this host; bit-identical cross-platform floating-point replay was not claimed. Balance goals and win rates are not yet playtested.
- Fullscreen standalone smoke view stayed black on this host; the windowed player rendered and worked. Use the documented windowed launcher. Project fullscreen/render settings were preserved instead of changing them. Player log showed stripped optional URP depth-of-field/Panini warnings; this prototype does not use those effects.
- The Mac locked before follow-up native inspection of the final marker/styling rebuild. Those changes compiled and built, but their final appearance was not rechecked; earlier windowed gameplay/control inspection passed.
